# LST Redesign Plan: T3s Onward — "Chain Tracking" (Edge-Classified T3 Graph)

**Date:** 2026-07-28 (session study; branch context: `lst019-review` @ 9810ef47bb3, ≈ SegmentLinking master + ExtendT5FromDupT5 speedup)
**Status:** Design proposal — not implemented. Produced by a multi-agent deep study:
8 parallel code readers → 4 independent designers (metric-clustering, GNN-lite,
conservative-unification, track-following) → 3 adversarial judges + completeness critic → synthesis.
**Companion artifacts (same dir):**
- `.lst_study_map.json` — 8-section code forensics (T3, T5, T4, pixel, NNs, dedup+TC, orchestration, jets), all claims file:line-cited.
- `.lst_design_panel.json` — 4 full design documents + 3 judge reports + 16-item blind-spot list.

**Goal:** replace everything from T3s onward with something that is
(C1) fast in high-pT jet cores, (C2) simpler than the current 6-NN + heuristic hodgepodge,
(C3) equal-or-better on displaced tracks (the top priority), (C4) more ML / less heuristic
(incl. killing the superbin pixel maps), (C5) equal-or-better timing on CPU *and* GPU,
(C6) equal-or-better final track lengths. MD/LS/T3 building stays (judged hard to beat).

## 0. The 16 problems with current LST this design fixes (executive summary)

Engineering fixes (1-10, 16) hold regardless of how well the NN trains; physics fixes (11-15) are
the upside, tested by P1 + the control experiment before any kernel is written.

1. **Zoo of DNNs** — six networks (t3dnn, t5dnn, t4dnn, pt3dnn, t5embdnn, plsembdnn) with separate
   trainings, feature sets, and exports → one training graph (~4k params: node encoder, edge
   scorer, chain gate, pixel head, dup projection).
2. **No use of track info past 5 layers** — t5dnn sees exactly 5 layers, tightCutFlag computed
   pre-extension, ExtendT5FromDupT5 grafts layers 6-7 AFTER every accept/reject → chain score
   accumulates edge log-odds + full-length fit over 4-9 layers (§5a).
3. **Scores not comparable across track lengths** — T4 and T5 judged by different nets on
   different scales; dedup tiebreaks need hacks (hand-added "longer wins") → one score family
   where length is evidence.
4. **T5/T4/pT3/pT5 object taxonomy** — separate builders, dedup kernels, crossclean kernels,
   SoAs → paths in one graph; pT5/pT3 become labels on a pixel attachment.
5. **Everything runs twice** — count kernel then create kernel recompute all cuts incl. the full
   DNN → exact edge count by degree arithmetic; nothing re-executed.
6. **Dense-module serialization in jets** — kNTripletThreshold=1000 path pushes a 300x300 MD onto
   one 256-thread block → flat edge-index decode spreads it over 90k threads.
7. **Memory explosion in jet cores** — O(h^6) builder writes ~150-byte persistent T5 slots (the
   reason the DNN had to run inside the counting kernel) → transient few-byte edges; rejects
   never touch memory; only surviving chains materialize.
8. **Truncation** — the 100k T5 cap, n_max_pixel_triplets=5000, n_max_pixel_quintuplets=15000,
   silently truncating in exactly the busy events → exact-count allocation + safety ceilings with
   DQM overflow counters (§5b).
9. **Quadratic serial dedup** — RemoveDupQuintupletsBeforeTC ~1e9 ops + the 12-kernel
   dedup/crossclean cascade → duplicates resolved as competing edges before objects exist;
   residual overlap by linear hit-claim arbitration (K9).
10. **Superbin pixel maps** — 45k superbins, 12 .bin files, host-side loops, hard-coded to the
    IP → analytic propagation of the pLS's own helix into an invariant-keyed grid (K8).
11. **IP-pinned selection killing displaced tracks** — betaIn/z1/eta1-type features in
    t3dnn/t5dnn and IP-referenced windows drive much of the 31.2% T3->T5 displaced kill →
    post-T3 features exclusively origin-free (IP features quarantined to the pixel head, where a
    pixel seed is legitimately an IP-region object).
12. **WPs anchored on the prompt-dominated population** — today's flattening holds prompt
    efficiency uniform while displaced efficiency is uncontrolled (the other half of the 31.2%
    kill; the 6x displaced loss weight defeated by its own threshold) → same WP-table mechanism,
    generated by script with per-dxy-decade targets alongside eta/pT (§5c).
13. **Training protocol rot** — object-level labels with duplicates as full-weight signal,
    row-level split leakage, WPs derived on training rows, hand-spliced tables, the embed eta/phi
    coordinate bug, norm constants from the wrong ntuple → track-level labels, event-level
    splits, held-out generated tables, shared feature builders + Python-vs-C++ parity test (§5c).
14. **High-pT tracks ignored in training** — small fraction of ttbar, no special handling, raw
    curvature uninformative above ~100 GeV → flat-pT/dijet enrichment, joint (log-pT x dxy)
    density weighting, curvature-significance features (§5c).
15. **No density context in any cut** — every current selection is per-pair, blind to being
    inside a jet core where fakes look prompt → per-node degree/neighbor aggregates fed to the
    edge scorer (the one genuinely new discriminating input; testable in P1).
16. **Host-sync choreography** — ~10 device syncs orchestrating count/create/dedup stages → ~4.

## 1. Diagnosis — why the current pipeline has these problems (code-verified)

### D-1. T5 builder pays its most expensive discriminator first, on every pair, twice
- `runQuintupletDefaultAlgo` (Quintuplet.h:1484): **first** cut is the t5dnn — ~40 SoA loads,
  ~1900 MACs, ~10 transcendentals, **unconditional per MD-matched pair** (Quintuplet.h:1539).
- Executed **twice**: CountTripletConnectionsT (dense/ReduceMem branch, Quintuplet.h:2082) + CreateQuintupletsT.
- Dense path (`kNTripletThreshold = 1000`, alpaka/Common.h:46; trigger Quintuplet.h:1768):
  a hot module runs the full algo per pair **serialized on one 256-thread block** — the event's
  GPU critical path (~6e5 serial FLOPs/thread on a 1000×1000-T3 module pair).
- Shared-middle-MD is a *scan test*, not an index (Quintuplet.h:1764; in-code comment: only ~3×
  rejection at warp granularity). Jet-core visits are **O(h⁶)** in core hit multiplicity h;
  MD-matched pairs O(h⁵), each paying the ~2000-FLOP prefix.

### D-2. Every η/φ prefilter is wider than a jet core
Windows are 0.1–0.5; a TeV jet core is ΔR ≈ 0.03–0.05. Inside the cone (exactly where combinatorics
explode) the **only** working discriminators today are hit-index compares and the 6-dim embedding
distance. (jets forensics §5i.)

### D-3. The dedup/crossclean cascade is a second quadratic
- `RemoveDupQuintupletsBeforeTC` (Kernels.h:508): global cross-module quadratic; the inner T5×T5
  loops are **plain serial per thread** (Kernels.h:530-540) — one thread owns n₁×n₂; two hot jet
  modules ⇒ 10⁴–10⁵ serial iterations/thread; ~10⁹ int ops critical path in dense events.
- 12-kernel cascade exists because over-enumeration yields ~2⁵ duplicate T5 variants per real track
  (2 hits/layer ambiguities), then repairs it post-hoc.
- Caps that silently truncate in jets (WARNINGS off in production): pT3 global 5000, pT5 global
  15000 (Common.h:34-35; enforcement PixelTriplet.h:797, PixelQuintuplet.h:701), extension
  kMaxCompatModules=40 (Kernels.h:287).

### D-4. Displaced kill concentrated in origin-pinned learned gates
Measured (session displaced study, PU200, 175 evts, geom-reachable = vxy≥5 cm & ≥4 OT simhit layers):
| stage lost | displaced | prompt |
|---|---|---|
| no MD | 3.8% | 0.1% |
| MD→LS | 5.0% | 0.1% |
| LS→T3 | 8.5% | 3.4% |
| **T3→T5** | **31.2%** | 10.8% |
| T5→TC | 8.6% | 0.9% |
| TC matched | 46.8% | 96.1% |
- t5dnn inputs include raw |η₁|,|φ₁|,|z₁|,r₁ (IP-frame) with prompt-tuned 2×10 WPs; it is the T3→T5 killer.
- dBeta selectors carry explicit `kDeltaZLum` beam-spot terms (~600 lines incl. runDeltaBetaIterations).
- passT5RZConstraint: 20-region prompt-fit χ² tables + tightCutFlag; T4: 25-bin table + dxy<0.05 anti-prompt veto.
- plsembdnn inputs are **100% IP-referenced** seed parameters AND it was trained on object-level
  sim-match labels mismatched to the TC-level dup definition (documented failure: physics χ² beat it
  for pT5 crossclean).
- Module connection map traced offline from 0.8 GeV **IP-origin** muon-gun helices
  (avg 13.9 / max 40 connections; `module_connection_tracing_merged.bin`) — upstream displaced
  acceptance bound; **out of scope here but the residual ceiling** (addendum in §9 Phase 6).

### Key calibration fact (settles all timing arithmetic)
Measured T5 stage = 33 ms CPU s=1 (count+create+extend+AfterBuild dedup). t5dnn ≈ 3.6 kFLOP/call,
unconditional per MD-matched pair ⇒ **typical MD-matched pair count E ≈ 2–5×10⁵/event** and
**effective single-thread MLP throughput ≈ 30–50 GFLOP/s** (zmm auto-vectorized; AVX-512).
The study-map's raw "1e6–1e7 calls" figure is a jet-tail bound, not typical. All estimates below
use 40 GFLOP/s CPU.

## 2. The four candidate designs and judge verdicts

Unanimous ranking across 3 adversarial judges (hw-timing, displaced-physics, simplicity):

1. **GNN-LITE (edge classification)** — WINNER / spine.
   Only measurement-calibrated budget; only design with zero absolute-position features post-T3;
   failure mode soft (truncation not merging); go/no-go measurable offline pre-C++.
2. **CONSERVATIVE-UNIFICATION** — #2 / first-PR + pixel + calibration machinery.
   Its Phase 1 is *provably output-identical* (pure AND-cut reorder); best superbin replacement
   (analytic helix propagation); honest padded numbers; lowest ceiling.
3. **TRACK-FOLLOWING** — killed as primary (CPU timing argument internally self-contradictory:
   claimed 5 GFLOP/s "matches measurement" — false by ~10×; at its own premise the follower eats the
   whole budget; plus unpriced hybrid-track tunneling in cores and a C1-voiding dense fallback).
   Three must-steal grafts (below).
4. **METRIC-CLUSTERING (union-find)** — killed as track-former: transitive closure means ONE
   accepted fake edge silently merges two real tracks into one TC; 2-means splitter cannot repair
   k≈25-track jet blobs; loosened T3 gate feeds the failure mode. Three grafts (below).

### Grafts adopted into the synthesis
- From **conservative-unify**: (G2a) output-identical CSR+flat-pair-queue+NN-last reorder;
  (G2b) χ²-computed-as-feature / threshold-tables-deleted pattern; (G2c) graft-on-merge inside
  overlap resolution; (G2d — REVISED, maintainer decision 2026-07-29) WP-generation-as-code:
  the binned eta/pT WP-table mechanism is KEPT (no score calibration/quantile remapping — rejected
  as work with no benefit); only the table *derivation* moves into a committed script.
- From **GNN-lite**: (G1a) degree-arithmetic exact edge count + flat binary-search index decode
  (kills double execution AND dense path); (G1b) degraded variant — per-node density aggregates at
  ~5 FLOPs/edge as classifier inputs; (G1c) offline edge-ROC go/no-go harness; (G1d) learned
  module-category embedding replacing raw z/r/η features and all per-region tables.
- From **track-following**: (G3a) propose-verify hit-claim arbitration (linear replacement for the
  whole dedup/crossclean cascade, deployable TODAY); (G3b) inward extension via incoming-LS CSR;
  (G3c) incremental O(1)-update circle-fit accumulators; (G3d) two-threshold attach (θ_attach vs
  θ_suppress); oracle-ceiling study methodology.
- From **metric-clustering**: (G0b) per-layer best-residual hit selection from pooled candidates;
  (G0c) origin-free helix-invariant pixel grid keys (φ_c, tanλ, signed log|κ|) with high-pT fallback;
  (G0d) geometric warm-start for embedding training; eff-vs-dxy flatness release gate.

## 3. Synthesized architecture ("Chain Tracking")

### Graph definition
- **Nodes** = accepted T3s (N_T3 ~ 1–2×10⁵ @ PU200).
- **E1 edges** ("T5 relation"): T3_i.md[2] == T3_j.md[0] (shared middle MD — exactly Quintuplet.h:1764's condition).
- **E2 edges** ("T4 relation"): T3_i.ls[1] == T3_j.ls[0] (shared LS — exactly Quadruplet.h:599-604's condition).
- A path of E1/E2 edges = a track of 4–9+ layers. T5, T4, ExtendT5FromDupT5, and all T5/T4 dedup
  collapse into one path formalism.

### Kernel plan (all Alpaka, flat/grid-stride unless noted; same source CPU+CUDA+ROCm)
| # | kernel | role | cost |
|---|---|---|---|
| K1 | BuildIncidence | MD→{T3 starting/ending}, LS→{...} CSR (count/prefix/scatter; existing pattern) | O(N_T3) |
| K2 | BuildEdges | exact count by E=Σ_MD deg_in·deg_out (**pure arithmetic — nothing runs twice**); flat edge-index decode via binary search over prefix array (perfect load balance — a 300×300 MD spreads over 90k threads); per-visit **~10-FLOP origin-free gate**: charge-sign agreement (with high-pT straightness bypass), asymmetric |Δ(1/R)| window (brems tail), resolution-weighted |Δtanλ| (PS/2S), thresholds @99.9% eff on prompt AND displaced sim; write edge records (i,j,type,8×half geo features) | O(h⁵) visits × 10 FLOP |
| K3 | NodeEncoder | φ_n: 12→24→16 (~750 MAC) per T3; latents 32B/T3 | ~6 ms CPU |
| K4 | MessagePass (OPTIONAL — only if offline ROC demands) | 1 round: ψ (16+16+8)→8 per edge, ρ (34)→16 per node; deterministic CSR-ordered segmented reductions (NOT atomic floats) | ~12 ms CPU |
| K5 | EdgeClassifier | φ_e (16+16+8[+6 aggregates])→24→1 sigmoid (~1000 MAC); **one** global threshold θ_edge | ~25 ms CPU @ E=5e5 |
| K6 | PathGrow | **mutual-best welding** (each node ≤1 in-weld ≤1 out-weld ⇒ paths, no transitive merging), 3 sweeps + second-best fallback; chain score = Σ log-odds + λ_len·nLayers; θ_chain | ~2 ms |
| K6b | RefineChains | (G0b) per-layer best-residual hit selection vs incremental chain fit (G3c); (G3b) **inward extension** at innermost MD via incoming-LS CSR; **per-layer shared-hit exemption** (≤2-way; conversions/2S-merged) | O(N_chain·deg) |
| K7 | ChainDedup | dual-keyed buckets ((η,φ) 0.05 cell AND first/last MD) + 6-dim projection head (linear 16→6, ~100 MAC) distance θ_dup; exact fallback confined to jet cones | ~2–10 ms |
| K8 | PixelAttach | pLS encoder 8→12 once/pLS; candidates via **analytic helix propagation** of the pLS's own stored helix (exact dz, continuous curvature, ptErr+MS window — computes what 45k superbins tabulate) into a device grid keyed on **origin-free invariants** (φ_c, tanλ, signed log|κ|; straightness fallback at high pT); 5-FLOP curvature pre-gate; pair head (12+16+6)→16→1; **two thresholds** θ_attach / θ_suppress (G3d); attached pLS consumed ⇒ crossclean structural | ~10–15 ms @1e5 pLS |
| K9 | ResolveOverlaps | (G3a) propose-verify hit-claim arbitration: packed (score\|length\|index) atomicMax per hit, 2–3 rounds, proportional acceptance; deterministic total-order tie-break; (G2c) graft loser's unique layers onto winner | O(N·hits) ≈1e6 atomics |
| K10 | AssembleTCs | chain+pLS→pT5/pT3-class; bare chain→T5/T4-class by nLayers; leftover quad pLS→pLS TC; positional 13-slot storage unchanged (downstream contract preserved) | O(TC) |

Host syncs: ~10 → ~4. No block-per-module serialization anywhere. No superbin host loops.

### NN inventory after (3 nets, ~4k params, ONE training graph)
1. **φ_n / ψ / ρ / φ_e + DupHead** (one PyTorch model): node features are exclusively origin-free —
   log10(R_circle), charge, chord-η (η of hit-to-hit *displacement*, never position), ΔΦ, dz, dr
   deltas, tanλ = dz₁₃/ds₁₃, and a **3-dim learned module-category embedding** (layer-triplet,
   PS/2S, barrel/endcap) that replaces raw |z|,r,|η|,moduleType AND all 20/25-region threshold
   tables. Explicitly EXCLUDED: |η₁|,|φ₁|,|z₁|,r₁, betaIn (the t5dnn/t3dnn IP-pinned features).
   Edge geo features: Δ(1/R), bridge-circle curvature, center-distance/mean-radius, Δtanλ,
   junction ΔΦ kink, shared-module category, edge type, layer-gap count. Density aggregates
   (deg_in/out, neighbor Δ(1/R) mean/min, gate margins) appended — **the in-cone context signal
   per-pair cuts structurally cannot access**.
2. **Pixel head** (pLS encoder + pair head): pLS features 100% IP-referenced — *acceptable here
   only*: a pixel seed is by construction an IP-region object; displaced ≥5 cm tracks have no pLS
   and never touch this net.
3. **DupHead** = linear 16→6 projection inside model 1's graph (contrastive, track-level labels).

Thresholds: the *loose* gates (θ_edge, λ_len, θ_dup, θ_suppress) are scalars set by a single
efficiency target. The *hard* decisions (θ_chain, θ_attach) use **binned eta/pT WP tables exactly
as today** — kept deliberately (maintainer, 2026-07-29): a flat cut on any raw score gives
non-uniform efficiency vs eta and pT; the binned WPs pin signal efficiency roughly uniform across
those axes, at the accepted cost of letting the fake rate vary. NO score calibration / quantile
remapping — score is used raw, the table carries the regional dependence. What changes is only
provenance and count: tables generated by a committed script on held-out events with per-track
(not per-object) efficiency targets, stratified in dxy as well as eta/pT; and there are ~2 of
them (chain, attach) instead of ~10 across six networks. Granularity: t5dnn-style 2 pT x 10 eta —
NOT t4dnn-style 2x25 dual tables (maintainer: "complete overkill", derived from 2-10 tracks/bin).

### What gets DELETED
- **Kernels:** CountTripletConnectionsT, CreateEligibleModulesListForQuintuplets, CreateQuintupletsT
  (both variants), ExtendT5FromDupT5, RemoveDupQuintupletsAfterBuild/BeforeTC,
  CountTripletLSConnectionsT, CreateEligibleModulesListForQuadruplets, CreateQuadrupletsT,
  RemoveDupQuadruplets*, CreatePixelTripletsFromMap, CreatePixelQuintupletsFromMap,
  RemoveDupPixelTriplets/QuintupletsFromMap, CrossCleanpT3/T5/T4/pLS, CheckHitspLS pass 2,
  host superbin loops (LSTEvent.dev.cc:807-877, 1077-1148), AddT5/T4/pT5/pT3 (→ one templated adder).
- **Physics machinery:** runQuintupletdBetaAlgoSelector + runDeltaBetaIterations (kDeltaZLum terms),
  passT5RZConstraint 20-region tables + tightCutFlag, passT4RZConstraint 25-bin table + dxy veto,
  pT5/pT3 rz/rφ/inwards χ² tables, PPBB/PPEE tracklet chains, score_rphisum ranking, isDup bitmask.
  (χ² COMPUTATIONS survive as NN features — G2b.)
- **NNs:** t5dnn, t4dnn, pt3dnn, t5embdnn, plsembdnn (t3dnn absorbed/replaced by φ_n at same site).
- **WP tables:** ~10 hand-made tables across 6 nets → ~2 generated tables (chain gate, pixel
  attach) + scalar loose gates. The eta/pT-binned WP *mechanism* STAYS (see Thresholds note above
  — it exists to flatten efficiency vs eta/pT and that need does not go away).
- **Maps/caps:** 12 pixelmap .bin files, PixelMap SoA, superbins (45000), 3 pixelTypes,
  n_max_pixel_triplets=5000, n_max_pixel_quintuplets=15000, kMaxCompatModules=40,

- **SoAs:** QuintupletsSoA, QuadrupletsSoA, PixelTripletsSoA, PixelQuintupletsSoA → edge list +
  chain CSR (memory ↓; keep 99.99th-pct safety ceilings + DQM overflow counters — see §6.7).

## 5. Displaced argument (C3)

1. The 31.2% T3→T5 killer (t5dnn gate) **does not exist**; successor φ_e has zero raw global
   coordinates on the critical path (chords/curvatures/two-circle consistency only). dBeta
   (kDeltaZLum), RZ tables, betaIn: deleted, not retuned.
2. pLS-less T5/T4 displaced population: chains are pixel-free objects; 4-layer (single E2) through
   9-layer chains under ONE uniform score with a length prior — replaces the T4 displaced-only hack
   + dxy anti-prompt veto.
3. **Inward extension** (G3b) recovers late-entry vxy 5–50 cm tracks — no current mechanism extends
   toward the beamline (ExtendT5 only grafts from duplicates).
4. Training: **track-level labels only** (edge positive iff both T3s MD-matched ≥2/3 to the SAME sim
   track) — direct fix of the documented plsembdnn object-level-label failure. Mix: PU200 RelVal +
   displaced-enriched flat-in-r vertex guns (muons AND hadrons; electrons + displaced kaons in the
   validation suite per blind-spot #2) with ≥25% of positive edges displaced; efficiency parity
   enforced in the loss, single WP.
5. Feature-hygiene rule (from displaced judge): audit EVERY feature for z₀/dca constructibility
   (e.g. tanλ+r₁+z₁ ⇒ z₀ = z₁ − r₁tanλ — the leak in 3 of 4 designs); designated ablation knobs;
   ship-ablated-if-deficit rule.
6. Release gates: eff-vs-dxy flatness (blocking); per-dxy-decade efficiency curves; the in-jet
   displaced metric (arbitration must not systematically lose contested hits to prompt tracks).
7. Honest ceiling: the IP-traced module connection map bounds LS/T3 acceptance upstream
   (46.8% is measured post-T3). Phase 6 addendum: union the map with displaced-helix tracing.

## 3b. Incidence build & edge enumeration — SPEED-FIRST implementation (maintainer decision)

Maintainer constraints: NO sorting anywhere (GPU sorts have repeatedly destroyed LST timing; even a
single small CUB radix sort ≈ 100 µs ≈ 5% of the 1.9 ms GPU event — rejected). Determinism is NOT
required if it costs speed (current LST is already nondeterministic in every atomicAdd-ordered
kernel: dedup winners, extension slots, pT3/pT5 cap truncation — so this loses nothing vs today).

Minimal-pass pipeline (all idioms already in-tree: count/prefix/scatter + flat kernels):
1. **Counts fused into the T3 builder**: addTripletToMemory's accept path does
   `atomicAdd(count[firstMD])` + `atomicAdd(count[lastMD])` (and LS analogs for E2). No separate
   counting pass ever runs.
2. **One prefix kernel** (existing single-block 1024-thread pattern) over MD counts; compute the
   per-MD edge products deg_end*deg_start AND their prefix in the same kernel → exact edge count E
   and the edge-ID→MD map, free.
3. **One scatter pass** over T3s: `slot = atomicAdd(offset[m])`, write T3 id. Arrival order —
   don't care (edge set is a cross product of slices, invariant under slice permutation; all
   tie-breaks elsewhere keyed by score).
4. **One fused edge kernel, rejects never touch memory**: launch exactly E threads; each
   binary-searches the product-prefix (few hundred KB, L2-resident, ~17 cached reads), decodes
   (inner,outer) by quotient/remainder, runs the 10-FLOP gate → cheap first-tier score → full head
   on survivors → appends ACCEPTED edges only via atomicAdd into an exactly-bounded buffer
   (accepted ⊆ E always fits). No edge materialization for junk; nothing executes twice.
5. Welding/arbitration with plain float atomics and packed atomicMax; first-arrival ties fine.

Hot-MD case (300×300) = 9e4 consecutive edge IDs scheduled like any others — no dense-module
special case exists. CPU serial: all atomics compile to plain ops; 3 linear passes ≈ ms-scale.
Determinism upgrade path IF ever demanded by HLT validation: fixed-point (int64-scaled) atomic
accumulators in the one order-sensitive kernel (message aggregation) + total-order tie-break keys —
zero sorts. Do not pay this until required.

## 5a. Evidence-ordered gating (maintainer priority — added after review)

Organizing principle (mirrors why today's pipeline cuts loose on t3dnn and hard on t5dnn, and why
pT3 is only viable because the pLS adds evidence): **loose cheap decisions at low evidence;
the hard irreversible decision at maximum evidence per candidate.**

- **Node gate (T3 level): loose** — combinatorics control only, the role today's t3dnn WPs play.
- **Edge gate (θ_edge): loose** — note an E1 edge already spans 5 MDs = t5dnn's evidence level,
  but its threshold is set for combinatorics/memory control (99.x% eff), NOT final discrimination.
  Ranking (mutual-best welding) does the local disambiguation, not the threshold.
- **Chain gate: HARD — the real discriminator.** Aggregates all edge log-odds + full-length fit
  residuals + length prior λ_len in one decision at 4–9 layers of evidence. A 4-layer chain faces
  a proportionally harder score demand (continuous version of today's per-type WP gradient).
- **Pixel attach: additive evidence.** A bare single T3 is never accepted (as today); it becomes a
  TC only if the attach head's pixel likelihood lifts the combined score — the generalization of
  why pT3 works without fake explosion. Attached chains get score credit; acceptance is
  evidence-conditioned, not type-conditioned.

Key advantage over baseline: **today's pipeline stops accumulating evidence at 5 layers** — t5dnn
only ever sees 5 layers, tightCutFlag is computed pre-extension, and ExtendT5FromDupT5 grafts
layers 6–7 AFTER all accept/reject decisions, so the extra layers never influence survival.
Chains invert this: a 7-layer track is accepted because 7 layers of consistent evidence say so.
Design consequence: P1's edge-ROC kill criterion applies to the CHAIN-level decision (edge gate
loose + chain gate), not to θ_edge in isolation.

## 5b. Memory & truncation (maintainer priority — added after review)

Context: today the only combinatorics truncation is the per-module 100k T5 reservation clamp
(kNQuintupletThreshold, cap_t5_100k work) added to avert jet-blowup allocation; it required
Stage-1/Stage-2 bound guards because the two-phase builder writes into a capped reservation.
The pT3/pT5 global caps (5000/15000) truncate silently in atomicAdd-arrival order, concentrated
in jet cores. Baseline memory ~250 MB/event PU200.

How the new design handles it:
1. **The quadratic object shrinks ~6× and duplicates never materialize.** Edge record ≈ 24–32 B
   vs ~150 B/T5; the 2⁵ duplicate hit-variants of a real track exist only as alternative edges,
   never as duplicated full track objects; only ~1e4 chains materialize. Deleted:
   Quintuplets/Quadruplets/PixelTriplets/PixelQuintuplets SoAs + preAllocated scratch (~20–40 MB)
   + connectedPixels map array (~4–40 MB). Added: edges ~12–16 MB typical (E=5e5), node latents
   ~5 MB, chain CSR ~5 MB. Net reduction.
2. **Exact allocation by pure arithmetic** (E = Σ_MD deg_in·deg_out) before any allocation —
   no count-kernel re-execution, no capped-reservation-vs-ungated-writer hazard class (the bug
   family the 100k cap's Stage-1 guard had to fix cannot exist: flat pair queue, index-decoded
   writes, no atomic racing into reservations).
3. **Truncation, when forced, is deterministic and physics-ranked, not arrival-order.** Keep
   per-collection safety ceilings at 99.99th-pct occupancy (HLT bounded-memory requirement,
   8 concurrent streams). If E_raw exceeds the ceiling: tighten the K2 gate working point for
   that event (99.9%→99.5% eff ≈ 2× fewer edges) or drop lowest-gate-margin edges — uniformly
   sheds the least track-like candidates instead of jet-core atomic-race losers; DQM overflow
   counter (never silent). pT3/pT5 caps die (attach exactly counted); pLS input cap and TC output
   ceilings unchanged.
4. **Honest worst case:** monster jet, per-MD degree ~300 over dozens of hot MDs ⇒ E_raw ~ few×1e6
   ≈ 50–100 MB edges — bounded by the ceiling + adaptive gate; failure mode is a deterministic
   ranked trim of the loosest ~0.4% of edges, vs today's serialized blocks + non-deterministic
   reservation truncation.

## 6. Blind spots to fold in (completeness critic — full list in panel JSON)

1. **Legitimate shared hits** (conversions, boosted τ, 2S merged): winner-take-all arbitration
   forbids them; add per-layer ≤2-way sharing exemption + conversion-sample efficiency gate.
2. **Electrons/brems & decays-in-flight** break constant-κ gates: asymmetric window
   (|κ_out|>|κ_in| tail), electron-gun + displaced-kaon samples in every kill suite.

   resolution-derived |κ| threshold; measure sign-flip rate vs pT in Phase 1.
4. **Loopers/curl-back** (0.8–1.5 GeV revisit layers): quantify; either declare out of acceptance
   with a number or add same-layer-revisit edge flavor.
5. **Amdahl**: post-redesign the optimum shifts upstream (pLS 334, MD 91, LS 76); event-level
   speedup saturates ~1.5–2× unless upstream also moves. State claims on touched scope.
6. **Determinism**: bitwise run-to-run + CPU-vs-GPU reproducibility as land criteria; CSR-ordered
   segmented reductions (no atomic-float sums); total-order (score|index) tie-breaks everywhere.
7. **Bounded memory**: exact-count allocation + 99.99th-pct per-collection safety ceilings with DQM
   overflow counters (caps were the de facto worst-case bound; don't lose that at HLT).
8. **ROCm**: parity gate per phase; no warp-width assumptions (wavefront 64 vs 32); template on

10. **Data-driven validation**: Z→μμ tag-and-probe, K_S/Λ displaced vertices; misalignment /

11. **Aging/hit-inefficiency**: killed-module stress test (1–2% random), dropout-style hit removal
    in training.
12. **Tails not means**: 99th-percentile event time on a jet-enriched skim as a land criterion.
13. **Cheap classical de-riskers to prototype FIRST** (they also improve the baseline): per-module

## 9. Why this is the right bet (context for future readers)

Every recent LST improvement has been converging on this design from below: embedding distance is
the only discriminator that survives in jet cones (dedup/crossclean/extension all adopted it);
pooling duplicate evidence makes longer tracks (extension kernel, +1.4% displaced); integer
topology prefilters beat float physics cuts (lst019 aligned-8-hit trick); object-level labels were
the wrong target (plsembdnn lesson). This plan makes those lessons structural instead of bolted on
— and its one genuinely new bet (learned local-density context replaces the IP prior for fake
rejection) is falsifiable offline for approximately the cost of one ntuple variable dump and a
minutes-long training run, before any kernel is written. If P1 fails, P0a+P0b are still worth
landing on their own.

### 10.3 Prototype structure (the Alpaka port must be mechanical, not a rewrite)
- One stage function per planned kernel K1-K10, each a pure function over flat arrays (indices
  in, indices out), no pointer-chasing object graphs, no hidden state between stages. Porting =
  wrap each function in a kernel + grid-stride the outer loop; logic is already validated.
- Single-threaded, deterministic. Location: `standalone/prototype/` (own small Makefile; ROOT I/O
  only, no Alpaka dependency).
- Same binary is the training-data factory: dumps edge/chain features + track-level labels for
  PyTorch, reads trained weights back (generated header or text), re-scores. Feature builders are
  shared between dump and inference within one binary — kills the embed-bug class (train/infer
  coordinate mismatch) by construction.
- What the prototype CANNOT validate (accepted residual risk for P2): atomic welding/arbitration
  race behavior, memory layout/occupancy, GPU timing, warp/block-level effects.

**Tuning priority (maintainer, 2026-07-31) — applies to EVERY cut/WP/threshold decision:**
1. **Efficiency (overall AND displaced) — dominant by a large degree.** When a cut trades
   efficiency against anything else, efficiency wins unless the cost is extreme.
   Displaced efficiency means the WHOLE vxy range out to the end of the plotted range,
   roughly 30-40 cm — the exact endpoint is not the point (maintainer, 2026-07-31): most
   displaced tracks sit at low vxy, so a single aggregate "displaced efficiency" number is
   population-weighted toward small displacement and can mask losses at large vxy — always
   judge the eff-vs-vxy CURVE across the full range, never one integrated number.
2. **Low duplicate rate — second.** Context: current LST dup rate is low and dominated by
   pLS/T5s not getting matched (TC-level matching misses), not by genuine object duplication;
   keep it low.
3. **Low fake rate — close third.** Cared about, but never bought with efficiency, and not
   prioritized over duplicates.

**Track length is a first-class metric too (maintainer, 2026-08-01):** alongside eff/dup/fake,
every A/B must compare TRACK LENGTH (tc_nhitOT / the harness "ol" avgOTlen set — goal C6:
