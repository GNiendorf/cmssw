WHAT IT DOES, IN ONE PARAGRAPH
  The weld gives each node one out-slot and one in-slot, so it can consume O(nNodes) edges, but the
  enumeration hands it sum_key degIn*degOut -- 3.8e8 rows / 8.4 GB on the worst jet event, of which
  0.018% are ever welded.  The capped path enumerates and scores in TILES and keeps, per node, only
  its C highest-keyed ELIGIBLE out-edges and C highest-keyed eligible in-edges (union of the two
  families, because an edge that is only its head's best still BLOCKS that head), then emits a
  compacted array.  Peak footprint becomes tile + 2*C*nNodes slots + kept rows: exact and
  sample-independent, instead of quadratic in the junction degree.

EXACTNESS, and what is NOT claimed
  NOT lossless by construction.  The rank a sweep's argmax reaches inside a node's own eligible list
  is 1 + #{higher-keyed eligible edges whose far endpoint was welded earlier}, which kChainWeldSweeps
  does not bound (see [M2 12:20] in FINDINGS_MEM.md).  C >= R is bit-identical by induction on the
  sweep; R is MEASURED (LST_CHAIN_RANK_CENSUS) and the shipped C comes from a 35-branch ntuple diff
  against the uncapped arm, not from an argument.
  Known residual assumption, shared with the shipped weld: node stableId is treated as collision-free
  (the tie word names an edge inside one node's list).  The capped path DETECTS a violation -- a
  surviving slot with no endpoint match is counted and reported -- which HEAD's weld does not.
