4. DEVICE MISSING-HIT NAVIGATION: DESIGN + FIRST PROTOTYPE PIECE
  What the host does per track (MkFitAlpakaOutputTrackConverter = stock MkFitOutputTrackConverter; 10 ms of the ~14):
    for (start layer, direction) in {(innermost hit's layer, oppositeToMomentum), (outermost hit's layer,
    alongMomentum)}: compatibleLayers(layer, fts, dir) [SimpleNavigationSchool], then for each compatible layer
    compatibleDets(tsos at the first hit, PropagatorWithMaterial(dir), Chi2MeasurementEstimator(30, -3 sigma bounds));
    the FIRST det returned becomes a missing (active) or inactive (MeasurementTrackerEvent: !isActive or
    hasBadComponents at the predicted point) hit in the pattern. NOTE: fts is the state at the FIRST hit for both
    directions. The pattern words feed lostInnerHits / lostOuterHits of the HP features (zeroing them flips 0.9% of HP
    decisions), and the reco::Track hit pattern (MTV, vertexing quality cuts).
  The navigation structure (read from RecoTracker/TkNavigation/plugins, SimpleBarrel/Forward/NavigableLayer.cc):
    - compatibleLayers = the closure (BFS, std::set of DetLayer pointers, <= 150 rounds) of nextLayers(layer, fts, dir)
      evaluated with the SAME fts for every layer; the returned order is the set's POINTER order (arbitrary, harmless
      for the counts).
    - nextLayers(layer, fts, dir) picks ONE of a few static candidate lists (Neg/Pos Outer/Inner, Inner/Outer
      Left/Right Forward, Inner/Outer Barrel) from direction bits of fts: transverse in-out (x px + y py > 0), z in-out
      (pz z > 0), sign(pz), dir. Along that list it propagates the ERROR-FREE fts analytically (AnalyticalPropagator) to
      each candidate surface (cylinder / disk), skips invalid or crossing-over propagations, keeps a candidate if the
      crossing is inside the bounds extended by the layer thickness term, and STOPS at the first one well inside.
  => Device design (ES table + per-track kernel; fixed capacities with overflow counters):
    (a) ES (once per IOV, host): per mkFit layer and key (dir, 3 bits) the static candidate list (<= 16 layer ids), and
        per layer the surface (barrel: radius, half length, thickness; disk: z, inner/outer radius, thickness). The
        lists are extracted from the NavigationSchool by enumeration (nextLayers on synthetic error-free states that
        cross no layer well inside, per key), validated on real tracks by the study below.
    (b) Kernel, thread per track, both directions: BFS over the table (bitset of <= 64 layers, no sets), per candidate
        a helix propagation of the state at the first hit to the cylinder/disk with the shared field (the device PCA
        header's TkBfield; the propagation is mkFit's propagateHelixToR/Z, or an exact helix as AnalyticalPropagator
        for rounding-level agreement), the bounds test with the thickness term.
    (c) compatibleDets on the device: per compatible layer, the modules near the crossing from the EventOfHits
        module table (phi/z bins for barrel rods/ladders, phi/r for disks), propagation of the state WITH ERRORS to the
        module plane (the port's propagateHelixToPlane + material as PropagatorWithMaterial), the -3 sigma shrunken
        bounds test (Chi2MeasurementEstimator(30, -3.0, 0.5, 2.0, 0.5, 1e12)), first det in the stock order.
    (d) Per-event inactive mask (one bit per module, from the MeasurementTrackerEvent's inactive pixel/strip module
        lists, filled on the host once per event or from the device cluster producers' bad-module lists) and the
        hasBadComponents test at the predicted point (pixel ROC / strip APV bad lists: per module bad-region tables).
    (e) Output per track: <= 4 + 4 (detid, type) entries; the host appends InvalidTrackingRecHit patterns from them
        (TrackerGeometry::idToDet, no navigation) and the HP features read the counts directly on the device.
    Judge: per-track lost inner/outer counts vs the host navigation (exact agreement fraction, the residual by layer
    kind) and the HP decision flips (the MkFitAlpakaHpCompare harness with the device features), switch-gated, then
    the O6-1 paired list. Expected difficulty ranking: (c) error propagation with material + -3 sigma bounds (edge
    cases), (d) bad components, (b) exactness of the stop rule near layer edges.
  First prototype piece (this round): plugins/MkFitAlpakaNavStudy.cc measures on real tracks (same first-hit states
  as the PCA check) that (1) an own BFS over nextLayers reproduces compatibleLayers, (2) per key (layer, dir, 3 bits)
  every nextLayers result is an ordered subsequence of ONE candidate list (the static-table premise of (a)), and (3)
  the sizes (fixed capacities). Results (ttbar 60 CPU: 85,158 tracks, 280,732 nextLayers calls; GPU ttbar 100 and
  QCD 100 the same picture): (1) closure == compatibleLayers for every track and direction, no 150-round overflow;
  (2) 164 keys (184 in QCD), 0 keys with a precedence cycle: every result is an ordered subsequence of one static
  candidate list per key (longest candidate list 10, <= 24 distinct results per key) => the ES table of (a) is
  sound; the TRUE order of layers that never co-occur must come from the school itself (TkLayerLess order), not from
  data; (3) compatible layers per track: inner/opposite 0 for 82% of the tracks, <= 9 in ttbar, <= 12 in QCD;
  outer/along 0 for 72%, <= 9 / 10 => capacity 16 with an overflow counter.
  Step (b) prototype (NAVSTUDY-EMU, CPU ttbar 100 + QCD 60): wellInside re-evaluated (A) with the stock
  AnalyticalPropagator, (B) with a device-style double helix (field z at the start point, AnalyticalPropagator's
  maxDPhi 1.6 rule, the same bounds/thickness/crossing-side tests):
    - every layer a call returned: A says "pushed" for 100% (the logic transliteration is right); B: 0 decision flips
      in 346,617 evaluations, crossing points within 3.8 um of A;
    - EVERY static neighbour of every visited layer (NavigableLayer::nextLayers(insideOut) + (outsideIn), i.e. the
      candidates of all branches, also those a call did not return): 6.55M evaluations, "pushed" flips 4 and
      "well inside" flips 2 (6e-7). Without the maxDPhi rule: 2,936 / 2,323 flips (4.5e-4): the rule is required.
      Remaining validity differences (~17k, where the stock propagator also rejects for other reasons, e.g. the
      curvature-change check or a far solution) never change a decision except those 6.
  End to end (NAVSTUDY-EMUSET): compatibleLayers EMULATED from the branch logic, the candidate lists REBUILT from the
  school's public static lists (nextLayers(insideOut) = NegOuter + the z > 0 endcaps of PosOuter, nextLayers(outsideIn)
  likewise, split by barrel / z side and re-sorted with TkLayerLess(insideOut / outsideIn) exactly as the school builds
  them), the stop rule and (i) the stock propagator or (ii) the device helix: the per-track compatible-layer SET equals
  the stock one for EVERY track and direction: 0 differences in 267,020 (ttbar) + 237,612 (QCD) cases, both with the
  stock propagator and with the device helix.
  ON THE DEVICE (plugins/MkFitAlpakaNavDevice.h portable, plugins/alpaka/MkFitAlpakaNavKernels.{h,dev.cc}, check module
  plugins/alpaka/MkFitAlpakaNavDeviceCheck.cc): table = 44 layers, 790 list entries (~23 kB, built on the host from the
  school's static lists + TkLayerLess); kernel = one thread per (track, direction), BFS on a 64-bit layer set, the
  helix + bounds + stop rule in double; REG 144-183, STACK 40-336, LOCAL 0. Result vs the host
  NavigationSchool::compatibleLayers with the converter's calls: CUDA ttbar 200: 0 differences in 531,834 track x
  direction cases; CUDA QCD 100: 0 / 391,418; serial ttbar 60: 0 / 170,316.
  => (a) + (b) are solved: an ES table per layer (10 index lists for barrel, 6 for disks, <= 44 layers -> a 64-bit
     layer bitset) + the helix + the bounds reproduce the host navigation's layer sets exactly. What remains is
     (c) compatibleDets with errors and material, (d) the inactive / bad-component mask, (e) the output.
  COST SPLIT (why (c) is next): the host compatibleLayers costs 0.48 us per call (NAVSTUDY-COST, ttbar, 2 calls per
  track) = ~1.8 ms per tracked event of the converter's ~14 ms navigation; the rest (~12 ms) is compatibleDets with
  PropagatorWithMaterial + the MeasurementTrackerEvent lookups (outconv r7: 2,464 calls per event). (a)+(b) on the
  device remove ~1.8 ms; (c)-(e) carry the remaining ~12.
  Step (c) requirements (plugins/MkFitAlpakaNavDetsStudy.cc, CPU ttbar 100 + QCD 60, the converter's calls and
  estimator): 156,547 / 172,539 compatibleDets calls, a det found in 74%, 3.9-4.1 us per stock call (= the ~10 ms).
    V1 AnalyticalPropagator instead of PropagatorWithMaterial: 0 found flips, 0 other first det => the device can
       propagate WITHOUT material;
    V2 the same state without errors: +16% found (25-28k dets the -3 sigma shrink rejects) and 5% other first det
       => the propagated position ERRORS are required (the -3 sigma bound shrink), but analytic ones suffice: the
       PCA prototype's AnalyticalCurvilinearJacobian + the curvilinear -> local plane Jacobian on the device.
  => (c) on the device = per compatible layer, the modules near the helix crossing (module table), per module the
     analytic helix to its plane + the analytic error propagation (no material), Chi2MeasurementEstimator's
     -3 sigma isInside test, first det in the stock order (GeometricSearchDet's compatibleDets order: next step to
     study per layer type).

5. WHERE THE DEVICE HP MASK GOES (the single sparse conversion)
  Today the HP features need the host reco::Track (PCA params and errors, lost hits). With the device PCA (2) and the
  device navigation (4) the features can be computed from the device fit's TrackSoA (hpsel's step-2 module already
  does the 5 exact ones), the MLP runs on them, and the HP mask decides on the device. Then ONE host conversion writes
  hltInitialStepTracks (all tracks; readers: vertices, MTV, cluster masking) with the pattern entries from (4e) and the
  PCA from (2), and the HP subset collection directly from the mask: the threshold module, TrackCutClassifier
  (passThroughForAll), the HP cloner and the one-collection TrackListMerger (3.1 ms) become one index pass. The
  merger's duplicate/shared-hit logic on a single collection (MinPT 0.8, MinFound 3, indivShareFrac 0.1,
  allowFirstHitShare) must then be reproduced or kept.

  Product (interface/outconv/OutConvSoA.h, dictionaries in MkFitAlpakaFormats + src/classes_def.xml): per row
    pcaState (x, y, z, px, py, pz float = GlobalPoint/GlobalVector of the PCA), pcaCov (15 float, reco::TrackBase

    the device: no synchronisation): interface/math/PcaToBeamLine.h =
      ccsToCurvilinear (mkfit::TrackState::convertFromCCSToGlbCurvilinear, float, the 6x6 Jacobian similarity) ->
      the field at the first-hit state from interface/math/TkBfield.h (the shared bitwise copy; outside its volume
      -> status host fallback) -> pcaToBeamLine (TSCBLBuilderNoMaterial: TTMD helix-line Newton, the EXT curvilinear
      Jacobian with vdt's DOUBLE fast_sincos now ported, C' = J C J^T).
    Precision detail that matters: the host's float sin/cos/atan2 are glibc's (correctly rounded in practice); the
    device's are 1-3 ulp. With device float trig, dsz pulls >= 1e-2 were 6.4e-3 of the tracks (GPU); with the float
    functions evaluated in double and rounded once (cosF/sinF/atan2F) they are 1.3e-4: a 50x reduction for free.
    Registers (sm_89): REG 255, STACK 104, LOCAL 0 (64-thread blocks: 16k registers per block).
  Converter: status ok -> the device state; host fallback or device failure -> the host TSCBL decides (as stock).
    pcaCheck (untracked) runs the host TSCBL for every track too and prints [outconv PCACHECK] at endJob.
  Beam spot (R7-L6): the converter (and stock MkFitOutputTrackConverter, hard-coded) read offlineBeamSpot, which the
    HLT job takes from the INPUT FILE (no producer in the menu dump). Decision: the device side uses the same product
    (the converter's new beamSpot parameter, default offlineBeamSpot, is passed to the producer), so stock physics is
    kept. Measured: offlineBeamSpot == hltOnlineBeamSpot (x, y, z, dxdz, dydz) in every event of every check job

    change with no effect on these MC samples and is what an online menu needs (offlineBeamSpot does not exist in
    RAW data); it changes the stock converter's behaviour on data, so it is left to the owner.
  Results: see REPORT.txt section 2 (PCACHECK on GPU and serial, ttbar + QCD; CPU A/B; GPU timing).

7.3 Ordering keys (ii): not built this round; the design is now concrete
  Size of the prize (converter timers split in round 9, GPU ttbar 500): hits 1.27 + keys+order 1.53 ms per tracked
  event; the device permutation removes the 1.53 (~1.1 box ms per input event).
  Where: the device fit's export (fitdev's FitKernels.h, the loop that walks hot[m] with ha.row(layer, index) and
  ha.es.modules[mod]): it has, per hit, the EventOfHits position (bitwise the legacy rechit globalPosition, verify7)
  and the module's raw detid (ES module table). Keys = (x, y, z), barrel = subdet in {PXB, TIB, TOB}, tiltedOrNotBarrel
  = TOB && tobSide < 3 (one bit per module, filled at ES time from TrackerTopology: the topology's bit layout is not
  public, so do not hard-code it). The same stable insertion as the converter, written as uint8 order[kMaxTrkHits]
  in a column next to the fit's rows (the OutConv SoA or a fit-export SoA). The converter then skips the keys and
  the insertion (hits+order section 3.2-3.8 ms per tracked event; the keys part ~2-3). Owner of the change: fitdev
  (the fit kernel) + es (the module bit). It cannot be done in a separate module without keeping the EventOfHits
  alive past the fit (lane mem's early delete) or recomputing the positions.
