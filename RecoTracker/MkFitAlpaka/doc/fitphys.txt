A. THE PF GAP OF THE mkFit-FIT MENU (R9-H1)
--------------------------------------------
Answer: it is the track ALGORITHM label, not the pT errors and not a PF cut.
  - RecoTracker/MkFit/plugins/MkFitOutputTrackConverter.cc:213-214 (stock) derives the algorithm from the seeds label:
      algo_{reco::TrackBase::algoByName(TString(seeds.label()).ReplaceAll("Seeds", "").Data())}
    In the Phase-2 HLT menu the seeds are "hltInitialStepTrajectorySeedsLST" -> "hltInitialStepTrajectoryLST", which is
    no algorithm name, so TrackBase::algoByName returns undefAlgorithm (TrackBase.cc:140-141). Offline the label is
    "initialStepSeeds" -> initialStep, which is why the rule works there. The KF menu's TrackProducer sets
    AlgorithmName = 'initialStep' explicitly (hltInitialStepTracks_cfi.py). Our converter copies the rule
    (MkFitAlpakaOutputTrackConverter.cc, customizeOutConv passes the stock seeds label): the target has the same gap.
  - PF: PFAlgo::createCandidatesHCAL (PFAlgo.cc:1967-1972) orders the block's tracks by dpt x
    PFTrackAlgoTools::errorScale(algo); errorScale returns 1.0 for initialStep / hltIter* and 1E9 for any algorithm not
    in its list (PFTrackAlgoTools.cc:86-114, "default: return 1E9"). With rejectTracks_Bad = True and pt_Error = 1 GeV
    (hltParticleFlowTmpBarrel), every block whose charged momentum exceeds the calo energy by more than nsigma_TRACK
    (= 1) x calo resolution drops undefAlgorithm tracks ("fabs(trk.first) < ptError_" never stops it: dpt x 1e9 >> 1 GeV)
    until the balance is restored, or rescales one (PFAlgo.cc:2297-2345). KF tracks (scale 1) qualify only with
    dpt > 1 GeV (badly measured, mostly high pT); a 1-10 GeV track has dpt ~0.01-0.1 GeV. That is the "~11 HP pT 1-10 GeV tracks per event", barrel only (|eta| < 1.5: the HGCAL side goes through
    TICL, where the algorithm plays no role).
  - The ~6% smaller mkFit-fit pT errors play no role (the scale is 1e9); the PF track quality cuts (GeneralTracksImporter
    goodPtResolution: dPtCut 5 instead of 10 for undefAlgorithm) are far from biting at 1% pT resolution.

B. D7: THE FIRST-HIT UPDATE AFTER AN INNERMOST-HIT OUTLIER REMOVAL (trackreco#186)
------------------------------------------------------------------------------------
Mechanism, stock code (RecoTracker/MkFitCore/src, #186 + #187):
  - MkBuilder::fit_tracks (MkBuilder.cc:1500-1513): one pass = fwdFitInputTracks (packs the candidate's CURRENT
    parameters, errors x 100, MkFitter.cc:40) -> fwdFitFitTracks -> reFitOutputTracks -> bkReFitInputTracks ->
    bkReFitFitTracks -> reFitOutputTracks(bkw). After a pass the stored state is the backward state ON THE INNERMOST
    hit's module (the first hit in reFitIndices order).
  - Outliers (MkBuilder.cc:1553-1573): hits with fwd + bkw chi2 > 20 (each > 8; pT <= 1: 15 / 7) are removed with
    Track::removeHit, the innermost one included; such tracks go to remap (:1580) and are refitted (:1681-1700).
  - MkFitter.cc:268 (fwdFitFitTracks; :462 bkReFitFitTracks):
        bool propHit = h == 0 ? false : true;  // just update when the position is already at the hit
    In the refit the comment is false when the innermost hit was one of the removed hits: the input state still sits
    on the REMOVED hit's module, and the first update of the refit is a Kalman update on the new first hit's plane
    WITHOUT propagating there. The residual then contains the path between the two modules.
  - Consequence: first-step chi2 ~1e3 - 1e6, the following steps go non-positive-definite (negative chi2 sums, NaN),
    and floating-point rounding picks the final state (the port's CUDA-vs-serial z tail of R7-M3: cm shifts with
    identical hits).
  - Fix (D7 mode 1): propagate to the first hit in the refits after outlier removal (propHit = true at h == 0 when the
    pass is a refit). The first hit's material stays skipped (no_mat_effs for index == indices.back(), as stock).
    Mode 2 = every pass (pass 1 too, see "related" below).

Stock reproduction (validation-only diagnostic: stock MkFitCore + env-gated prints, MkFitCore branch
r10/fitphys-diag 01fe691, built into L/r10_fitphys/libs/diag and preloaded; MKFIT_FITPHYS_DIAG=1 prints, for every
refit and every 16th pass-1 track, the signed distance of the input state to the first fit hit's module plane and the
first-step chi2; MKFIT_FITPHYS_FIRSTHITPROP=1 applies the fix to the refits). Stock trackingMkFitFit menu, CPU, ttbar
