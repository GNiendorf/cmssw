lstin: stage-B prototype, LST's input built on the device (round 6, lane lstin)
================================================================================
WHAT
  plugins/alpaka/MkFitAlpakaLstInputProducer.cc (+ MkFitAlpakaLstInputKernels.{h,dev.cc}) produces
  lst::LSTInputDeviceCollection (the product hltLST consumes) on the device, instead of the host chain
    hltPhase2PixelTracks (legacy reco::Track) -> hltInitialStepSeeds (host KF refit = SeedFromConsecutiveHitsCreator)
    -> hltInputLST (host packing: LSTInputProducer + lst::prepareInput).
  It is OFF by default: nothing in the menu changes unless the lane customise is applied
  ($L/r6_lstin/cfg/customizeLstIn.py, customizeLstInDevice(process, mode=...), modes compare / timing / replace).

INPUTS
  hltSiPhase2RecHits (host, legacy OT rechits)  -> staged LOCAL quantities only (local x/y, GeomDet index, cluster size,
                                                   raw detId), no toGlobal on the host
  hltSiPixelRecHits (+ its hit-module-start)    -> pixel SoA row -> legacy cluster key map (inverse of the hitmap of
                                                   PixelTrackProducerFromSoAAlpaka: row = moduleStart[det] + originalId)
  hltPhase2OtRecHitsSoA (hit-module-start)      -> OT-SoA row -> legacy OT hit index map (the SoA holds only the P
                                                   sensors of the TOB PS modules, in detUnit order)
  hltPhase2PixelTrackTorchHighPuritySelector    -> Patatrack device tracks (state at the beam-spot PCA + covariance)
  hltPhase2PixelRecHitsExtendedSoA (device)     -> hit global positions (beam-spot frame) for the outermost hit
  per IOV: a module table (Surface rotation rows + position + raw detId per GeomDet index), copied to the device.
  NOTE: the OT rechit SoA (hltPhase2OtRecHitsSoA) is NOT usable for the LST OT hits: it holds only the PS P-sensor hits
  of the OT barrel (Phase2OTRecHitsSoAConverter), while LST needs every OT hit. The legacy OT rechits are host-made
  (Phase2TrackerRecHits); the device transform uses r5's mkfitdev::localToGlobal (fma pattern fma(a,b,c*d)).

OT HITS: bitwise equal to hltInputLST (x, y, z, detid, clustsize, idxs) on every hit, CPU and GPU (see REPORT).

pLS, OPTION (i) = Patatrack's own fit (what the kernels compute per tight track; formulas as LSTInputProducer):
  PCA: position bs + (tip sin(phi0), -tip cos(phi0), zip), momentum pt (cos phi0, sin phi0, cot theta), q = sign(q/pt);
       dxy = -tip, dz = zip (relative to the beam spot, as the host's TSCBL values)
  last hit: the outermost hit of the track (Patatrack order is inside-out; the host seed sorts by radius - the hit keys
       of all host pLS are found in this order, so the order agrees); position = the hit (host: the KF state on it);
       momentum = tangent of the uniform-field helix (Patatrack's field, fieldInInvGev at the origin) at that hit
  ptErr / etaErr: the host formulas of LSTInputProducer applied to the perigee (rho, theta) errors derived from the
       Patatrack covariance: var(rho) = k^2 c(q/pt), cov(rho,theta) = k sin^2(theta) c(q/pt,cot), var(theta) =
       sin^4(theta) c(cot) (k = Bz in GeV^-1 cm^-1). The host "ptErr" is pt*p*sigma(rho)-like, not sigma(pt): kept as
       the host defines it (LST's cuts are tuned on it).
  selection: quality >= tight and finite state (as hltPhase2PixelTracks), then LST's ptIn > ptCut - 2 ptErr and the
       pixelType rule; superbin with the host's mixed float/double expressions; pseudo-hits as lst::prepareInput.
  ordering: Patatrack SoA order (the host orders by pT through PixelTrackProducerFromSoAAlpaka's std::sort), made
       deterministic by a chunked serial scan (no atomics in the indices). seedIdx = Patatrack SoA track index.
OPTION (ii) (device refit with our mkFit fit code): NOT implemented this round (see REPORT, next steps).

MODES (validation)
  compare : the device collection is copied back and compared with hltInputLST per event (LSTIN_CMP lines; OT hits
            bitwise; pLS matched by their stored hit keys = first three + last hit); per-pair values go to dumpFile;
            a second LST (hltLSTDevIn) runs on the device input and MkFitAlpakaLstInputTCCompare prints LSTIN_TC
            (TC counts per type host input vs device input, and identical OT-hit lists per type).
  replace : physics-test arm for O6-1: hltLST runs on hltInputLST's collection in which every pLS matched by hit keys
            gets the device (option i) parameters and pseudo-hits; OT hits, the pLS set, order, seedIdx and hit keys
            stay the host ones, so LSTOutputConverter (which still reads hltInputLST's OT rechit pointers and the
            hltInitialStepSeeds copy) and the mkFit chain are unchanged. LSTIN_REPLACE lines count replaced/kept pLS.
  timing  : the producer only (nothing consumes it), for its own host cost.
  on      : the switch ON form: hltInputLST leaves the menu. seedsFromHost = True: pLS only for pixel tracks that have a
            host seed (SoA row -> hltPhase2PixelTracks' SoA->edm map -> hltInitialStepSeeds index, identity when the
            counts agree, else matched in order by the first seed hit), seedIdx = that seed index, and a host product
            'otRecHitPtrs' (an LSTInputHostCollection holding only the OT rechit pointers) for LSTOutputConverter, which
            reads lstInput = hltInputLSTDevice:otRecHitPtrs and lstPixelSeeds = hltInitialStepSeeds.

PRODUCER FORM
  stream::SynchronizingEDProducer: acquire() = host staging into pinned buffers, H2D copies, the per-track pLS kernels and
  the D2H copy of the counts (LST needs exact collection sizes); produce() = allocation of the collection + fill kernels.
  The module table is copied to the device once per IOV and stream. Clusters are read by key (no Ref deref per hit).

BUILD NOTES
  - Do not <use> RecoTracker/LSTCore in plugins/BuildFile.xml: linking LSTCore's CUDA library into our plugin library
    made every kernel launch of the plugin fail (cudaErrorInvalidResourceHandle). Only header-only LST types are used
    (LSTInputSoA, TrackCandidatesSoA, Common.h), reachable through the include path.
  - Eigen/Core must be included before any SoA header (TracksSoA has Eigen columns).
  - Never rebuild a plugin library while cmsRun jobs use it (both running jobs segfaulted at the relink).

    keys (99.99-100%); ~0.3% device-only pLS (no host seed / below the host pT cut).
  - Option (i) vs the host KF seeds: pT +0.47% median, 1.6% width; eta 0.0036; phi 0.8 mrad; dz/dxy widths 2.0 mm / 300 um

  - OT module table: the shared ES product of MkFitAlpakaEventOfHitsModuleTableESProducer (moduleTable =

ASYNCHRONOUS PRODUCER (task item 1): NOT done, by analysis. The producer is an ExternalWork (SynchronizingEDProducer) module:
  the counts readback does not block a thread. LST itself (LSTProducer, global::EDProducer) blocks its thread in 46
  alpaka::wait calls (LSTEvent.dev.cc) and reads the input sizes on the host first (pixelSize_ = size()[1], nHits =
  size()[0]: hit and pixel-segment allocation, the pixel MD slot 2*pixelSize_, the superbin/pixelType copies). Without a
  readback the input must be allocated at capacity with device-side counts, and LST must read them back itself (one
  blocking wait at its start): the sync moves into LST and costs a blocked thread instead of an ExternalWork callback.
  It pays only together with an asynchronous LST. Needed LST changes, for the record: LSTInputSoA scalars nPixelSeeds /
  nHitsTotal; LSTEvent::addInputToEvent reads them (or LST keeps capacity sizes and every kernel loops to the device count:
  HitLoopKernel, AddPixelSegmentToEventKernel, the pixel MD slot set by a kernel).
SHARED OT STAGING (task item 1, second half): NOT done (lane cpu is changing MkFitAlpakaEventOfHitsProducer's fillRaw this
  round). Design: one producer of the OT hits' local quantities in legacy order (local x/y + errors, GeomDet index, rawId,
  cluster size/key) as a host product + device copy, read by the device EventOfHits (deviceHits) and by hltInputLSTDevice
  (+ the OT rechit pointer product for LSTOutputConverter). Saves the second host loop over ~250k OT hits (~1.2 ms per
  tracked event in round 6).

ROUND 9 (lane lstin, 2026-10-04 8:30 - 10:45 am): stage-D input, creator-failure emulation, pT3 tracer
================================================================================
All switch-gated, OFF by default (nothing changes unless a customise below is applied).
1. OT hits from the device OT rechit SoA (otSoA). With stage D (customizeOTDev / customizeOTDevFull, or the target's
   OT_DEVICE) hltInputLSTDevice reads otdev's mkfitdev::OTRecHitDeviceCollection (row = cluster key = legacy rechit index)
   directly on the device: x/y/z = the SoA's gx/gy/gz (Surface::toGlobal with contractGlobal = CONTRACT_LST, the same
   variant hltInputLST's otSoA path copies from the host copy), detid = detId, clustsize = clustSize, idxs = row. No host
   pass over OT rechits, no OT staging buffers or H2D copies, no module table for the OT hits. The CA OT row -> key map
   (pixel tracks' OT extension hits) comes from the cluster detset sizes (one pass over detsets, P modules only).
   The 'otRecHitPtrs' product has no OT rows in this mode: LSTOutputConverter must make its OT hits on demand
   (otClustersOnDemand = full stage D); the customise refuses lazy/on modes otherwise. Apply customizeLstIn AFTER the
   stage-D customise (customizeOTDevFull refuses a menu where hltInputLSTDevice still reads hltSiPhase2RecHits).
2. Creator-failure emulation (R7-H2 change (ii)): RecoTracker/LST local patch LSTPixelSeedFailMask (host EDProducer,
   label hltPixelSeedFailMask) lists the hltPhase2PixelTracks whose hltInitialStepSeeds seed the host creator would
   reject; hltInputLSTDevice (seedFailMask) gives them no pLS, as stock (no seed -> no pLS). The recipe is the shared
   RecoTracker/LST/interface/LSTProtoTrackSeed.h (also used by LSTOutputConverter's lazy seeds, so the two cannot drift).
   Pre-filter: the creator runs only on tracks with two consecutive radius-ordered seed hits closer than maxDr = 0.05 cm in
   radius (round 8: every rejection is such a near-degenerate pair; FastHelix + the first KF steps fail there);
   maxDr < 0 runs it on every track (exact by construction). validate = True also runs it outside the pre-filter and
   counts misses (LSTMASK_MISS).
   Customises: customizeLstInDeviceLazyMask (lazy + mask, maxDr 0.05), ...LazyMaskAll (maxDr -1), ...LazyMaskCheck
   (lazycheck + validate).
3. pT3 tracer (RecoTracker/LSTCore local patch, validation only): LST_PT3_TRACE=1 in the environment of a CPU (serial)
   job prints at exit one LSTPT3TRACE line with the per-cut counts of CreatePixelTripletsFromMap ->
   runPixelTripletDefaultAlgo (pLS considered / isDup / partOfPT5, pairs tried, fails at radius, inner tracklet, outer
   tracklet, rz chi2, DNN, pass). Compiled out on GPU backends; a cached flag test per call when unset. Change (i) is
   traced by two CPU jobs on the same events: OFF (host pLS) vs 'replace' (host pLS set, option-(i) parameters).
4. 'otdev' (customizeLstInDeviceOTDev, NO physics change, needs full stage D): hltInputLST stays (pLS from the host seeds
   exactly as stock) but with otKeysOnly (RecoTracker/LST local patch: OT rows carry only detId + cluster size per cluster
   key, which the pixel seeds' OT hits read; x/y/z left 0; no OT SoA host copy, no legacy rechits); hltInputLSTDevice
   (fromHostInput) copies that host collection to the device and fills the OT rows (x/y/z/detid/clustsize/idxs) from the
   device OT rechit SoA; hltLST reads hltInputLSTDevice. The converter still reads hltInputLST's host product (seeds, OT
   pointers = nullptr, OT hits on demand under full stage D). Validation: customizeLstInDeviceOTDevCheck runs an
   unpatched clone (hltInputLSTRef) and compares every column (LSTIN_FULLCMP).
