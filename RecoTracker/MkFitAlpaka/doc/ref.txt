1. VERIFICATION OF THE REFERENCE
1a. -Ofast on every MkFitCore TU (verbose compile lines; R/verify/compile_flags.txt, tool R/scripts/check_flags.py <log>)
    new reference, x86-64-v3 and x86-64-v2 builds: 22/22 TUs  -O3 ... -Ofast -fno-reciprocal-math ... -fopenmp-simd
      (ofast-flag tool = "-Ofast -fno-reciprocal-math"; it comes after -O3/-fno-math-errno, so the effective set is
      -Ofast minus reciprocal math: associative math, finite-math-only, no signed zeros, no trapping math; shared
      libraries do not get crtfastmath, so no flush-to-zero).
      IterationConfig.cc is -Ofast too (the release's FILE= exception never worked, see 1b).
    stock BuildFile (r6_base/MkFitCore_BuildFile.xml.orig, rebuilt from the same sources): 0/22 TUs with -Ofast;
      every TU = -O3 -fno-math-errno -fno-reciprocal-math -fopenmp-simd (REM_CXXFLAGS="-Ofast" FILE="IterationConfig.cc"
      strips -Ofast from the WHOLE package) = what the release CMSSW_20_1_0_pre2 ships. Confirms O6-5.
    MkFitCMS and MkFit (CMSSW glue, plugins incl. MkFitFitProducer) have no ofast-flag in stock either: -O3 only.
    The lane area's libRecoTrackerMkFitCore.so is byte-identical to the v3 build of a second copy (cmp).
1b. Parsed IterationConfig of the LST step, with and without -Ofast (R/itconf/, tool test/ref_itconf_dump.cpp)
    The tool parses RecoTracker/MkFit/data/mkfit-phase2-lstStep.json exactly as MkFitIterationConfigESProducer does
    (ConfigJson::load_File, minPt 0.9 -> minPtCut, maxClusterSize 8, setupStandardFunctionsFromNames) and prints EVERY
    field (scalars, IterationParams fwd/bkw incl. raw bytes, 5 regions' steering plans, 60 layer configs with
    selection limits and window parameters, function names and which functions are set) with floats as hexfloat, then
    the library's own JSON serialisation. One binary, run against three libRecoTrackerMkFitCore.so builds:
      Ofast x86-64-v3 (the reference) | NO -Ofast x86-64-v3 (stock flags) | Ofast x86-64-v2 (the floor build)
    -> 1114 lines each, md5 identical (53b96ad2...). The parsed IterationConfig does not depend on -Ofast (nor on v2/v3).
    So the ESConfig our ES producer flattens from it (field by field, src/esFill.cc) is unchanged too.
1c. Size of the reference shift (stock + #186 + #187 + Ofast vs plain stock pre2) on the replay chain: section 3.

  Reading:
   - The shift is large and mostly #186 in BUILDING: +0.77% candidates, 1.85% of the paired candidates change their hit
     list (the material r-z box fix of MkFitGeometryESProducer and/or the new field constants, which building uses
     through bFieldFromZR), and the final fit moves a lot (q/p pulls 0.1-1 sigma typical). Paired truth: the new
     reference finds 1392 TPs the old one misses and loses 126 (per 100 ttbar events): efficiency up ~0.19% absolute
     on all in-time TPs; fake and duplicate rates unchanged within 0.0001.
   - -Ofast alone is invisible in building (2e-5 of the candidates) but NOT in the final fit: with -Ofast ~50-60 fitted
     tracks per 100 ttbar events (3e-4) come out non-finite and MkFitOutputTrackConverter drops them (28-30 true TPs
     lost per 100 events, +4e-5 efficiency without it). -fno-finite-math-only alone restores them (c1: 190473 vs 190469
     without -Ofast). So restoring -Ofast in MkFitCore (Dan Riley's planned PR) costs fit tracks unless the fit is made
     NaN-safe or MkFitCore keeps -fno-finite-math-only. Our port's CPU flags (O6-3) already have -fno-finite-math-only:
     expect the port to KEEP these ~3e-4 tracks, i.e. to show up as "tgt-only" fit tracks against this reference
     (the chained floorFit has 6+6 unpaired per 100 events).
  Default (KF) menu, CPU, ttbar 500 events, same RAW events, new reference vs plain vA (R/menu/results/shift_def_cpu_ttbar.txt):
     hltGeneral 617395 -> 619444 tracks, eff 0.8876 -> 0.8881, fake 0.0089 -> 0.0090, dup 0.0104 -> 0.0103;

     17 vertex DQM histograms > 3 sigma (vertex counts +17..73 of 25-37k). So #186 is NOT KF-menu neutral: its building
     changes reach the KF menu through the candidates. (The plain-vA side = the pre2_4way vA outputs of the same
     job.sh command line on the same 5 files, harvested by r5_menu: stockcpu_ttbar.)
  3b. Split of the shift (chunk c4, 100 ttbar events): the new reference with ONLY the field constants set back to the
     pre2 values (MkFitGeometryESProducer bFieldParams = 3.8114, -3.94991e-06, 7.53701e-06, 2.43878e-11; R/cfg/
