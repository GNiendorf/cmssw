1. WHAT THE CUSTOMISE DOES (D4-menu)
  Base: the exact val5k command line of lanes/pre2_4way/scripts/job.sh (75e33_timing, one-step HLT + DQM, no extra
  procModifier); the port adds --customise RecoTracker/MkFitAlpaka/customizeHLTforMkFitAlpaka.<function>.
  Module swaps, menu labels kept (every downstream InputTag resolves unchanged):
    hltMkFitEventOfHits                        MkFitEventOfHitsProducer -> MkFitAlpakaEventOfHitsProducer@alpaka
                                               (useESLayers, ES product hltMkFitAlpakaES)
    hltMkFitEventOfHitsHost (new)              host MkFitEventOfHits for the stock converters: io's hit-less
                                               MkFitAlpakaLightEventOfHits (LIGHT_EVENT_OF_HITS_PLUGIN), or a clone of
                                               the stock producer when the stock MkFitFitProducer is scheduled
                                               (trackingMkFitFit without the device fit)
    hltInitialStepTrackCandidatesMkFitDevice   the device building module (BUILD_PLUGIN: build's
                                               MkFitAlpakaBuildProducer@alpaka; round-3 MkFitAlpakaChainProducer has the
                                               same parameters)
    hltInitialStepTrackCandidatesMkFit         MkFitProducer -> MkFitAlpakaOutputWrapperFromTrackSoA (host
                                               MkFitOutputWrapper; the stock MkFitOutputConverter reads it unchanged)
    [fit] hltInitialStepTrackCandidatesMkFitFit MkFitFitProducer -> MkFitAlpakaFitProducer@alpaka; refused while
                                               DEVICE_FIT_HAS_CPE is False unless customizeHLTforMkFitAlpakaFitNoCPE
                                               is used (D4-H1). Lane fit flips the constant when the CPE lands.
    ES: hltMkFitAlpakaESProducer (MkFitAlpakaESProducer@alpaka, ComponentName hltMkFitAlpakaES)
  The two new producers sit in a Task associated with HLTInitialStepSequence: they run on demand, i.e. exactly in the
  events where the menu runs the initial step (332/500 ttbar events).
  Checks at customise time: the stock MkFitProducer must be inside the validated envelope (cloneEngine, no CMSSW
  backward fit, seed cleaning on, duplicate removal on, no clustersToSkip, empty minGoodStripCharge, the LST-step
  IterationConfig label); after the swap no host module may still read the device hltMkFitEventOfHits.
  Variants: customizeHLTforMkFitAlpakaEventOfHits (device EventOfHits next to the stock one, compareTo the stock:
  the first step, physics untouched by construction), customizeHLTforMkFitAlpakaValidation (production swap + the stock
  chain scheduled after the initial step, on its own full EventOfHits hltMkFitEventOfHitsStock, + comparators +
  paired truth; the port runs in its exact production configuration).
  Pitfall found: an on-demand stock reference in an EndPath fails, because the menu's early deletion
  (customiseEarlyDelete, appended by cmsDriver after the customise functions) has already deleted MkFitHitWrapper
  when the EndPath runs ("Found zero products ... hltMkFitSiPixelHits"). The validation variant therefore schedules the
  stock reference + comparators at the end of HLTInitialStepSequence; only the paired-truth module is in an EndPath
  (it needs the VALIDATION associator) and it skips events without tracks.
