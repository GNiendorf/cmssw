8. (b) DESIGN: THE pLS DEVICE SEED STATE (not implemented this round)
   What 7 shows: Patatrack's fit and the KF seed differ by ~1 mm in z0 (endcap, low pT) and the LST pLS cuts were tuned on
   the KF values. Moving Patatrack points around (helix, anchor) cannot reproduce a KF. The (b)-method answer is to RUN
   the D2 device fit on the pixel-track hits BEFORE LST, inside hltInputLSTDevice, and to build every pLS field and
   pseudo-hit from its result:
   - input: per tight pixel track its hits (Patatrack SoA rows -> legacy cluster keys, already mapped: pixKey / otKey)
     in the creator's order (radius order, includeFourthHit as hltInitialStepSeeds); hit positions + global
     covariances from the device EventOfHits hits (the same rows mkFit uses; DEVICE_HITS is ON in the target);
   - fit: LstSeedFit.h host-structure mode (originPrior 3 = FastHelix through the region origin, the creator's initial
     errors, ONE forward KF pass, the creator's rejections rejDPhi / rejBackward), the PIXEL region of
     SeedGeneratorFromProtoTracksEDProducer (origin = the proto track's vertex, its pT; R8 L1 notes);
   - outputs: the KF state on the last hit = r3LH / p3LH / ptIn / ptErr / eta / phi / deltaPhi; then TSCBL with the
     menu field (stagec's device PCA kernel of the output converter does exactly TSCBLBuilderNoMaterial on the device:
     reuse it) = dxy, dz, p3PCA, r3PCA, superbin. This makes the pLS fields KF-like by construction (the D2 known
     regression level, not Patatrack-vs-KF);
   - creator-failure rule: a pixel track whose device fit is rejected gets NO pLS (as stock: no seed, no pLS). Measured
     against LSTPixelSeedFailMask with maxDr < 0 (the host creator on every pixel track = exact): a confusion table
     (device reject / host fail) per event; r8 counted 141-145 host failures per 100 ttbar events, 140 at |eta| >= 1.6,
     all with the first two radius-ordered hits within 0.05 cm (FastHelix near-degenerate), so the rejection logic
     must reproduce the creator's FastHelix degeneracy handling. The host mask (3.7 ms) then goes;
   - the pLS seed state for mkFit: the light pLS seed in LSTOutputConverter (hits only, placeholder state) and the
     device fit replaces it in the build module, as T5/T4/pT3/pT5 today (D2); hltInitialStepSeeds (15.9 box ms) and
     hltInputLST (3.5) leave the menu; the lazy creator in the converter goes too.
   Cost: one forward KF over 3-5 hits for ~1,200 tight pixel tracks per event: small next to LST.
   Order of work: (1) the kernel in hltInputLSTDevice + the compare dump of 7a (device KF vs host KF state per pLS:
   expect the D2 pull tails, |1/pT pull| > 1 in ~3%); (2) the confusion table vs the mask; (3) the pT3 tracer (target:
   OFF's 27,086 within ~1%); (4) O6-1 (ttbar + QCD 500).
