D1  NaN guards of the final fit are dead in the -Ofast stock build; the port keeps them (round 6, lane fit)
    Stock (source):
      - MkFitter.cc:102  reFitOutputTracks: if (m_Chi2 != m_Chi2) continue;  // "trick for the nan so the track is
        not dead": a fit pass whose chi2 sum is NaN keeps the track's previous state;
      - MkBuilder.cc:1545-1548 (fit_tracks outlier block): chi2fwd / chi2bkwd NaN -> 1000000 before the scorer.
    Stock (binary): MkFitCore is built with -Ofast (ofast-flag, now applied to the whole package as the mkFit developers
      intend). -Ofast implies -ffinite-math-only, under which GCC folds x != x (and std::isnan) to false. Both guards
      are removed: the NaN state is written into the track, and NaN per-hit chi2 enter the outlier scorer (NaN keys in
      the std::map scorerAndIdx).
    Effect (replay ttbar, 100 events, 193,069 fitted tracks, stock + #186 + -Ofast): 59 tracks come out of the stock
      final fit with NaN parameters (0 in the port); MkFitOutputTrackConverter drops them (reco::Track level: the port
      has 60 tracks that stock has not, 4 the other way). Excluding the 59 NaN tracks, port vs stock is at the rounding
      level (|pull| >= 1: x 12, theta 10, 1/pT 14 tracks; CUDA vs serial of the port: 14 / 12 / 17).
    Port: the same source checks (FitKernels.h fitDirection / removeOutliers). They work because the device code is
      compiled without -ffinite-math-only (CUDA strict; CPU backends -Ofast -fno-finite-math-only, D5-a / O6-3).
      So the port does what the stock source says. No code change in the port; markers at both checks.
    Proposed stock fix (lanes r6_fit/patches/0001-MkFitCore-NaN-guards-...patch): mkfit::isNaN(float), a bit test
      that survives -Ofast (cms_common_macros.h), used at both places. With it, stock == port (see doc/fit.txt R6).
    Other x != x / std::isnan tests in MkFitCore (MkFinder.cc building, debug code) are equally dead under -Ofast;
      not audited here (building lanes).

  Stock: MkBuilder.cc fit_tracks outlier block (r6_base :1540-1575) and fittracks remap loop (:1660-1680).
    - A hit is an outlier only when BOTH one-sided chi2 are large (pT > 1: f > 8 && b > 8 && f + b > 20; pT <= 1:
      7 / 7 / 15). For the first and the last fitted hit one of the two passes starts there from the x100-scaled
      prior, so its chi2 is ~0: an end hit can never be removed, however bad.
    - One round: outliers are removed after pass 1, the track is refitted once, and the refit is never checked.
    The KF final fit (KFFittingSmoother) rejects any hit with an unbiased chi2 > EstimateCut 20, end hits included, and
    iterates until none is left. The selection (Torch HP) then sees mkFit-fit tracks with outlier end hits: true-track
    chi2/ndof > 10 in 1.8% (KF 0.1%); the HP selection drops 2.2-2.4x more true mkFit-fit tracks than KF tracks; that is
    the whole efficiency gap of the mkFit-fit menu (r7_fitgap/REPORT.txt 3, doc/fitgap.txt 3).
  Port (FitKernels.h removeOutliers / outliersAndRefit / KernelFinalFitStage, FitTracks.dev.cc; markers D3; switches

      is > 20, the last one when the FORWARD chi2 is > 20; the 3-hit minimum and the scorer ranking are unchanged;
    - outlierRounds = 3: removal + refit repeated; the last refit is not checked (as d2a08a4's remap loop).
