=====================================================================================================================
Branch r8/mem (RecoTracker/MkFitAlpaka). Scripts and logs: L/r8_mem/{scripts,logs,memattr,menu/runs}.

1. WHAT HOLDS THE MEMORY (R7-H1 step 1)
  The device EventOfHits product (hits 48 B/hit + binnedHits 20 B/hit + bin table 5 B/bin, ~31 MB per ttbar PU200
  event, one caching-allocator block rounded up to a power of two) is read by exactly two modules, the device building
  and the device fit, but as an event product it lived until the end of the event: with 16 EDM streams in flight that
  is up to 16 blocks at any time, although each event needs it only between the EventOfHits kernels and the end of the
  fit kernels. The engine scratch (EngineBuffers x2 + K2 list/props/sels) is already freed at the end of the build's
  produce(); the build and fit TrackSoAs are a few MB.
  On the CPU backends the same product is one fresh 31 MB allocation per event; jemalloc serves allocations >= 8 MiB
  from an arena that purges them on free, so every event re-faults all of its pages (doc/cpu.txt 5 and 9: ~9 ms/event).

2. GPU: THE DEVICE EVENTOFHITS IS DELETED RIGHT AFTER THE DEVICE FIT
  - python/customizeMemory.py customizeMkFitAlpakaEarlyDelete (called by customizeHLTforMkFitAlpakaTarget when
    EOH_EARLY_DELETE = True, the default): lists the product in process.options.canDeleteEarly (the framework's early
    deletion, as customiseEarlyDelete does for the stock mkFit products), so it is deleted after its last consumer, the
    device fit, and its block goes back to the caching allocator. Branch names = edm friendly names per backend
    (cuda / rocm DeviceProduct of the PortableDeviceCollection, serial: the pooled host type of section 3); names
    absent in the job are ignored by the framework. Applied only if the device building and the device fit are the
    product's only consumers (validation customisations with more readers keep the old lifetime).
  - Queue safety. The caching allocator orders the reuse of a freed block after a marker on the queue the block was
    ALLOCATED on (the EventOfHits producer's queue). A block read by kernels on another queue could be handed to a third
    queue while still read. So:
    - the building gets the EventOfHits before calling iEvent.queue(), and the fit gets the building's TrackSoA before
      iEvent.queue(): both take over the producer's queue (EDMetadata queue reuse) and the chain EventOfHits -> build
      -> fit runs on one queue;
    - the EventOfHits producer puts a host product "queue" (the native queue handle; 0 on CPU backends); the fit
      (eventOfHitsQueue set by the customise) compares it with its own queue and, if different, waits for its work
      before returning (EOH_RELEASE sameQueue / waited at endJob; LogWarning on the first wait).
  - Output identical by construction (same kernels, same order on the device; only the lifetime changes).

3. CPU: THE EVENTOFHITS PRODUCT IN PER-STREAM POOLED MEMORY
  - CPU backends: EventOfHitsDeviceCollection = mkfitdev::EventOfHitsPooledHostCollection (interface/EventOfHitsProduct.h):
    the PortableHostCollection interface (view, const_view, buffer() of exact size), but its buffer can be an
    alpaka::BufCpu into a block of the producer's per-stream pool, whose deleter only drops a reference to the block.
    The block (grow-only, +25%, 64 KiB granularity) stays resident between the events of the stream: no re-faulting.
    GPU backends keep the PortableCollection.
  - Safety: an EDM stream starts its next event only after the current event's products are gone (and the CPU queue is
    blocking), so a block is never used by two events. Every row a consumer reads is rewritten every event (HitSoA: all
    rows by the device-hit kernel or fillHits; layers: fillLayers + the CPU build kernel; bins: the whole table;
    binnedHits: the registered rows, the only ones read through the bin table).
  - scratchReuse = 0 on the EventOfHits producer restores the per-event allocation.
  - Dictionary: mkfitdev::EventOfHitsPooledHostCollection and its edm::Wrapper (src/classes_def.xml, transient).
  - Known limit: a HOST module that consumes mkfitdev::EventOfHitsHostCollection from a serial_sync EventOfHits
    producer (test plugin MkFitAlpakaProductsCheck of integ_products_cfg.py) no longer finds it on the CPU backend
    (the product type differs there); the menus have no such consumer (the customise refuses host consumers).

5. NOT DONE / NEXT
  - The CI shape (4 jobs x 16 x 16) was not run (lane limit 2 jobs); menu lane: rerun gpumem2.sh on the merged head.
  - The largest ttbar EventOfHits product is 39.6 MB, above 32 MiB: on GPU the caching allocator serves it from a
    64 MiB block (power-of-two bins). Shrinking it below 32 MiB, or splitting it into a hits product (the fit's only
    input, deleted after the fit) and a binning product (deleted after the build), would cut the block held in the
    EventOfHits -> fit window by up to half.
  - The build's TrackSoA (read by the fit) is not deleted early: the menu still schedules the host wrapper of the
    building (hltInitialStepTrackCandidates.tracks consumes hltInitialStepTrackCandidatesMkFit), whose host copy reads
    the same device product.
  - The default (KF) menu (customizeHLTforMkFitAlpaka): the build is the last consumer there; the same early deletion
    needs the queue guard in the build module (not done).
  - EventOfHits rows per ttbar event (139 tracked events): median 436k, p90 497k, max 560k hits; product = 68 B/hit +
    ~1.5 MB, so events above ~470k hits (~25-30% of ttbar) take a 64 MiB caching block instead of 32 MiB.
  - Any NEW device consumer of the EventOfHits (e.g. a stage-C module) makes customizeMkFitAlpakaEarlyDelete refuse

  - R7-H1 (3), one arena for the engine scratch: not done. The scratch is transient (freed when the build's work is

6. THE OT RECHIT SoA IS DELETED RIGHT AFTER THE EVENTOFHITS (customizeOTSoAEarlyDelete, OT_EARLY_DELETE)
  - What held the memory: full stage D's device OT rechit SoA (MkFitAlpakaOTRecHitsProducer, hltMkFitAlpakaOTRecHits;
    module, detId, size, strip, local position / errors, global position = ~46 B per OT cluster, ~11 MB per ttbar PU200
    event, a 16 MiB caching block) was an event product, so every event in flight held one (+1.1 GB peak at the CI shape,
    verify8_int 6c). Its device reader is hltMkFitEventOfHits (the hit fill kernel); hltInputLST reads the framework's
    host copy (made by the producer's transform). The CA OT layers read the producer's OTHER products (CA hit SoA,
    hitModuleStart), which are unchanged.
  - customizeOTSoAEarlyDelete (python/customizeMemory.py; called by customizeHLTforMkFitAlpakaTarget after
    customizeOTDevFull when OT_DEVICE and OT_EARLY_DELETE are set) lists the SoA's branches (cuda / rocm device product,
    the host collection = serial product and host copy on GPU backends) in process.options.canDeleteEarly. Applied only
    if every reader of the producer's label is known: the EventOfHits (otSoA), an LSTInputProducer (otSoA, host copy),
    the CA OT layer parameters (trackerRecHitsSoA, outerTrackerRecHitSoAConverterSrc). Any other reader: nothing changed
    (printed).
  - Two hazards, two guards:
    (a) the transform is not a consumer the early deletion knows about. If hltInputLST asked for the host copy after
        the EventOfHits had run, the device SoA would be gone. So the EventOfHits consumes the host copy (otSoAHost, not
        read): the framework makes the copy before the EventOfHits runs, i.e. before the deletion.
    (b) the caching allocator orders the reuse of a freed block after a marker on the queue it was ALLOCATED on (the OT
        producer's queue). The EventOfHits usually runs on another queue (the transform or the CA consumer takes the
        producer's queue first). The OT producer now puts a host product "queue" (native handle, as the EventOfHits
        does since round 8); the EventOfHits (otSoAQueue) records an event on its queue right after the fill kernel
        (the last read of the SoA) and makes the producer's queue wait for it on the device (cudaStreamWaitEvent /
        hipStreamWaitEvent). The free's marker comes later on that queue, so no other queue can reuse the block before
        the fill kernel is done. No host wait. Counters at endJob: OT_RELEASE sameQueue N ordered M.
  - Output identical by construction (same kernels in the same order; only the lifetime and a device-side queue order
    change). Checks: section 8.

  - Replaced (in the sequences that hold it directly) by MkFitAlpakaStatusCheck on the build's status
    (hltInitialStepTrackCandidatesMkFitStatus, requireClean False): the same per-event LogWarning on a non-zero counter
    (review H4) + one summary line at the end of the job. Refused (printed) if any reader of the wrapper is in a
    sequence, path or task.

    (eventOfHitsQueue, customizeMkFitAlpakaEarlyDelete), the TrackSoA is deleted after the fit too. The guard covers it:
    the fit runs on the EventOfHits queue, which the build took over and allocated the TrackSoA on, or it waits for its
    own work before returning.
  - Path module lists, target+D menu: 14 paths differ, each only by wrapper -> status check; nothing else.
