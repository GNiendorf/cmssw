MkFitAlpaka - lane bkfit: backward fit + propagation/Kalman numerics (round 3, 2026-10-03)
======================================================================================
Reference: stock mkFit of CMSSW_20_1_0_pre2. Round-1 notes of the propagation/Kalman primitives: doc/prop.txt.

1. WHAT IS HERE
  src/alpaka/bkfit/BkFitKernel.h   the port of MkBuilder::fit_cands (usePropToPlane branch, backward_fit_to_pca off) =
                                   MkFinder::bkFitInputTracks(EventOfCombCandidates&) + bkFitFitTracksProp2Plane
                                   (MkFinder.cc:1991-2020, 2450-2665). Generic over an IO object:
                                     BkFitCandsIO  production: clone-engine SoAs (best cand = slot (s, curBuf, 0),
                                                   compacted HoT chain in the seed's pool) + the engine's
                                                   EngineHitInputs (section 5)
                                     BkFitFlatIO   self-contained records (stock-replay test)
                                   Kernel BkFitKernel<IO>: one Alpaka thread per kNN candidates (1 on GPU, 8 on CPU),
                                   the stock Matriplex loop; block size 64.
  src/alpaka/bkfit/BkFitLaunch.h   host entry points backwardFit(...) (production, in place) and backwardFitFlat(...);
                                   makeEngineBackwardFit(hits, pflags) = the engine's EngineBackwardFitFn;
                                   backwardFitFlags(hostESConfig, deviceMaterial) = PropagationConfig::backward_fit_pflags.
  src/alpaka/bkfit/BkFitTypes.h    FlatCand / FlatNode / FlatOut records.
  src/alpaka/BkFit.dev.cc          the only TU that instantiates the bkfit kernels (D-layout).

  Contract with the clone engine (call order of stock runFunctions.cc:78-87):
    pre-bkfit filter -> compactifyHitStorageForBestCand -> backwardFit -> beginBkwSearch -> backward search.
    Input per seed s with nCands > 0 and overflowBits == 0: best candidate (state + book) in slot (s, curBuf, 0),
    its chain from book.lastHitIdx through HoTNode.prev in the seed's pool (hotRow(s, n, hotsPerSeed)).
    Output in place: state.par / err / charge; book.chi2 = backward-fit chi2; book.score = getScoreCand(book, pT).
    Nothing else changes (chain, counters, curBuf, nCands).

2. STOCK BEHAVIOUR REPRODUCED (review H3; all of it verified against stock dumps, section 3)
  a) bkFitInputTracks scales the input errors by 100 (MkFinder.cc:2019 m_Err[iC].scale(100.0f)).
  b) chi2: reset to 0 at input (MkFinder.cc:2015) and then ACCUMULATED over the backward-fit updates
     (MkFinder.cc:2662 m_Chi2.add(tmp_chi2)). So the forward chi2 is replaced by the backward-fit chi2; the score is
     recomputed with it (MkFinder.cc:2499-2504). Correction to review H3 b), which said the chi2 stays 0: the stock dump
     has the backward-fit chi2 in every candidate (the first port without the add matched 0% of the scores).
  c) Same-layer runs collapse to the EARLIEST node (MkFinder.cc:2513-2516): overlap hits never enter the fit.
     343k same-layer hit pairs in the 214k ttbar candidates of the dump.
  d) kalmanCheckChargeFlip after every update; the propagation fail flag is not checked (PROP-FAIL-ENABLE comments).
  Not reproduced on purpose: nothing. The stock loop over N slots (done slots keep being propagated with stale hit
  data) is kept on CPU; it cannot change a result because slots are independent and a done slot is copied out first.

5. PRODUCTION PATH AND THE ENGINE HOOK
  BkFitCandsIO reads the engine's own hit inputs (EngineHitInputs: x..e22, packed, nPixel, layers[].isPixel /
  moduleBegin, modules[].nrm/dir/pnt; row = engineHitRow) and hotsPerSeed from the SoA scalar, exactly as the
  engine's K3 does. The engine plugs it in with
      EngineBackwardFitFn bkfit = makeEngineBackwardFit(inBkw, backwardFitFlags(hostESConfig, deviceMaterial));
  (src/alpaka/bkfit/BkFitLaunch.h) and passes it to engineRunChain.
  Test: the device test also loads every event of the dump into SeedCands/CandSlots/CandHots collections and a
  synthetic EngineHitInputs (same numbers), runs backwardFit and requires bit identity with the flat path:
  214576/214576 ttbar and 235255/235255 QCD, serial and CUDA.
  D-M4 decision in the test: BKFIT_FLOOR=<outputs of the v2 stock re-run (BKFIT_RERUN_OUT)> makes the exit status
  "port vs stock(v3) no worse than stock(v2) vs stock(v3)" on every fraction from 1e-5 up, chi2, charge and
  finiteness (2-sigma binomial slack). PASS on ttbar and QCD, serial, CUDA L40 and CUDA L4.
  Command lines: $L/r3_bkfit/REPORT.txt.

6. H6: FP64 IN THE 2x2 CRAMER INVERTER (GPU)
  The backward fit inverts one 2x2 per hit (kalmanOperationPlaneLocal). Kernel time, ttbar 214576 cands, best of 30:
                                         L40        L4         physics vs stock(v3)
    stock: double det, double 1/det      0.881 ms   2.129 ms   (section 3)
    double det, float 1/float(det)       0.878 ms   2.118 ms   unchanged within 0.1% on every fraction
    float det, float 1/det               0.874 ms   2.108 ms   fractions unchanged; worst candidate 1.2 -> 11.5
  The FP64 share is <= 1% of the backward-fit kernel on both GPUs: not worth a change. Kept stock (no code change;
  the study build switch was removed). The per-operation prop test kernels are memory bound (~0.85 ns/slot for every
  op on the L40), so they cannot resolve it either. If K3 ever shows a larger share, variant 1 is the candidate
  (no visible physics effect); variant 2 moved the worst candidate and would need the DEVIATION path.

7b. SCORER CHECK
  getScoreCand (interface/cands/CandTypes.h, as the kernel calls it) on stock's OUTPUT chi2 and pT reproduces stock's
  score bit for bit on the device: 214576/214576 ttbar, 235255/235255 QCD, serial and CUDA. The same expression
  compiled as HOST code in the CUDA test binary (nvcc host pass) matches only 92.7% / 93.5%: the stock score is
  FMA-contracted (gcc -Ofast, x86-64-v3) and that host pass does not contract the same way. Harmless for the port
  (the score is computed on the device), but a warning for any host-side re-scoring in a CUDA-built translation unit.
